## Public API

The API permits one token to belong to more than one sequence. `llama_model` owns weights and vocabulary; `llama_context` owns inference state. ## Internal path: batch metadata → attention → output

1. **Validation and microbatch allocation.** `src/llama-context.cpp:4618-4626` delegates public `llama_decode` to `llama_context::decode`. `src/llama-context.cpp:1817-1996` validates the batch, allocates output rows, prepares memory, and processes microbatches. `src/llama-batch.cpp:28-236` copies token, position, membership, and output metadata into internal arrays and validates IDs. `src/llama-batch.cpp:244-314` forms the unique sequence IDs and microbatch view. Position ordering is checked at `:447-488`.
2. **KV memory.** `src/llama-kv-cache.cpp:916-1114` finds cache slots by sequence/stream. `llama_kv_cache::apply_ubatch` at `:1115-1176` stores each token position in a cell and adds its sequence IDs to that cell. The separate-stream layout maps IDs to streams; a unified KV layout can share a buffer, while membership still controls visibility. `src/llama-context.cpp:4262-4270,4387-4409` implements the public memory access, removal, and copy wrappers; `src/llama-kv-cache.cpp:400-545` has the KV implementation.
3. **Mask construction.** `src/llama-graph.cpp:30-46` creates the attention mask tensor. Graph input setup calls the memory context's `set_input_kq_mask` at `src/llama-graph.cpp:537` (and related architecture paths). `src/llama-kv-cache.cpp:1759-1796` fills the tensor. In `set_input_kq_mask_impl` at `:1569-1715`, a candidate key cell is dropped to `-INFINITY` if it lacks the query's sequence ID (`:1663-1666`). Independently, with causal attention, a future key position is dropped when `p0 > p1` (`:1679-1683`). An allowed pair gets zero mask bias (`:1706-1714`). Thus sequence membership and causality are separate conditions. The token's ID is used to look up cache membership; the public API does not itself manufacture the tensor.
4. **Attention operations.** `src/llama-graph.cpp:3108-3165` copies K/V into memory, retrieves them and passes the filled mask to `build_attn_mha`. The verified final CPU run explicitly disables flash attention. Its ordinary path at `src/llama-graph.cpp:2927-2962` applies `ggml_soft_max_ext` with `kq_mask` after QK multiplication. The optimized path at `:2883-2907` passes the same mask to `ggml_flash_attn_ext` when enabled. Backend kernels implement those graph operations; the source above shows the mask supplied at that boundary.
5. **Logits and sampling.** `src/llama-context.cpp:2161-2206` maps requested batch entries to contiguous output rows. `src/llama-context.cpp:4218-4229` resolves `llama_get_logits_ith`. In the custom test, `src/two_prompt.cpp` records each prompt's final batch index, takes the argmax of that row, and retains separate positions, tokens, and termination state. The upstream example uses `llama_sampler_sample` at `examples/batched/batched.cpp:191`.

The preliminary `auto` flash setting produced a reproducible Prompt B mismatch; disabling flash attention made both prompts match exactly in normal, reversed, and repeated batches. Details and logs are in `part1_report.md`. The source path establishes that cross-sequence keys are masked. Exact greedy output can still differ when a different attention kernel and batch shape change numerical execution enough to reorder close logits.
